# Kotlin renderer capability declaration

This declaration describes the current Compose registries. Registration means a tester and renderer are present; it does not certify every option or target interaction. The [registry inventory](renderer-registry-inventory.json) records every entry and its order, the [registration guide](renderer-registration.md) documents ranks and escape-hatch namespaces, and `node scripts/check-renderer-registry.mjs` detects registry drift. Requirement-level evidence and open behavior are in the [spec ledger](spec-requirement-ledger.json) and [behavior catalog](renderer-behavior-catalog.md).

## Contract provenance

The contract uses `@chobantonov/jsonforms-extended-spec` version `0.2.0`, pinned by the root `package-lock.json` and [source inventory](spec-source-inventory.json). Its `v0.2.0` source tag is commit `e0b23861ca0c47d17309202c5dbb2111364b3286`. That spec reconciles a neighboring React renderer fork at commit `e931e46c237f371dc283c291746640d653a32190`; the spec package's `provenance.json` records which reference documents were used. A behavior appearing in that fork or in the sibling Svelte implementation is not, by itself, an upstream JSON Forms guarantee. The Kotlin capability claims below refer to this pinned extended contract and executed Kotlin evidence.

| Contract surface | Origin under spec §5.2 | Kotlin declaration |
| --- | --- | --- |
| Base `Control`, `Group`, `Categorization`, `HorizontalLayout`, `VerticalLayout`, `Label` and `scope`/`rule` structure | Core JSON Forms element model | Parsed in shared core; mounted rendering is family specific. This origin does not certify every renderer option. |
| Material/Cupertino input presentation, built-in choice widgets and options such as `multi`, `toggle` and `slider` | Renderer convention, with individual upstream provenance unverified | The two Compose families declare their own tester ranks, options and target limits in the [behavior catalog](renderer-behavior-catalog.md). Presence in a neighboring fork is not attributed to upstream. |
| Group `cover`/`header`/`footer` card regions, input adornments, named `Template`/`Slot` and `jsonformsExtended` configuration | Extension defined by the pinned spec | Shared model/resolution plus separate Material/Cupertino rendering; requirement rows and target tests in the [ledger](spec-requirement-ledger.json) bound each claim. The card and adornment fixtures have English/Bulgarian mounted evidence. |
| AG Grid, Monaco and executable JSX/Ractive `TemplateLayout` | Optional web-only extension contracts; Kotlin engine support is unverified and currently unsupported | Both families expose the explicit diagnostic/fallback listed below. The [browser integration review](web-only-integration-review.md) records the DOM lifecycle and browser tests needed before any JS-only adapter changes status. |

This table records provenance for these capability groups. The [behavior catalog](renderer-behavior-catalog.md) contains entry-level selection and option evidence where audited; a complete option-by-option provenance audit across every registry entry is still open. No Kotlin-specific vendor option bag is declared as a portable spec namespace.

## Families and targets

| Family | Runtime | Evidence boundary |

The base families register `Control`, `ListWithDetail`, `Label`, `Spacer`, `Group`, `Categorization`, `HorizontalLayout` and `VerticalLayout` presentations. Controls cover scalar text, numeric, boolean, enum, combinators, objects, arrays, tuples and mixed schemas. The portable selections registered in the current families include multiline, switch, radio, autocomplete, slider, password, date/time/date-time, chips, multi-select, stepper, accordion and splitter. A registered presentation can still have option-specific limits; consult the linked behavior catalog and ledger before claiming a particular workflow.

Groups accept top-level `cover`, `header`, and `footer` regions. Material and Cupertino render them in a single card with the body and keep cover and heading visible during collapse. Region children use ordinary renderer dispatch; data and validation indicators aggregate only body `elements`, including when regional controls contain data or have validation errors. The demo editor preserves these regions on UI-schema export. The shared input fields in both families render literal or localized text adornments inside the field boundary in authored order, and show an icon's label when no native icon mapping exists. Decorative icons without a mapping are omitted. The separate Material choice fields use the same normalized start/end slots, and Cupertino uses its shared field. The 98 mounted Group/adornment cases pass in each of JVM, JS browser, Wasm browser, and iOS simulator. They include Group-level DISABLE/HIDE rules across every region, regional visibility rules, nested field writes, host readonly transitions, Group-owned readonly propagation to regional text, boolean, enum and radio controls, and readonly nested header/footer layouts with `separateReadonlyFromDisabled`; core §15.1 precedence still permits an explicit child `readonly: false` to override inherited state. They also cover body-only Group indicator changes, wide-to-240 dp heading/footer wrapping in one card, imported cover ImageView alt text and 100% card-width frame with its authored URL policy, plus decoded imported cover pixels in standalone Web Component and Wasm demo Chrome tests, imported footer Button dispatch of `setLocale` without data writes, live English/Bulgarian translation, full imported adornment fixture mounts, picker/reveal action checks, and 240 dp LTR/RTL geometry for text, choice, password, date, time, date-time, integer stepper, decimal stepper, duration, cron and color fields showing logical edge reversal with no native-action overlap. Tooltip focus leaves the 240 dp text field and adornment bounds stable. Group expansion changes only when the effective collapsed option changes, so an initial effect cannot undo a quick disclosure click. The first authored header Label now supplies the Group accessible name, using the same live English/Bulgarian translation as the rendered Label; four mounted cases per target cover collapsible and static cards on JVM, JS browser, Wasm browser and iOS simulator.

## Validator profile

Both families use the shared `OptimumCodeJsonSchemaValidator` through JSON Forms core. It delegates JSON Schema evaluation to the OptimumCode Kotlin Multiplatform validator. The integration honors a declared `$schema`, infers draft-07 for legacy positional `items`, and otherwise selects 2020-12 for a generic `$schema`. It enables format assertions, registers `iso-time`, `iso-date-time`, `cron` and `color`, and adds the temporal comparison keywords described in the [validator notes](../README.md). This is a Kotlin validator profile; it does not claim full Ajv plugin compatibility. The spec's authoring artifacts and imported draft-07 example schemas are checked offline by the separate pinned Ajv gate. General Ajv `$data`, transform, dynamicDefaults and function-bearing schema keywords are not declared as supported Kotlin validator extensions.

## Named browser integrations

| Profile | Material and Cupertino, all declared targets | Observable fallback |
| --- | --- | --- |
| AG Grid `variant: "ag-grid"` | Unsupported as AG Grid | Selects the portable array table, preserves data, displays a localized English/Bulgarian notice and reports `variant.unsupported`. Portable columns, pagination and row detail have separate evidence. |
| Monaco `options.format: "code"` | Unsupported as Monaco | Displays `editor.monacoUnavailable` and delegates to a native applicable control without rewriting the value on mount. |
| JSX/Ractive `TemplateLayout` | Unsupported as a template engine | Preserves the authored payload, displays a localized fallback and reports unknown language, disabled evaluation or unavailable engine. Named Template/Slot is a separate portable feature. |

The visible fallback notices and emitted diagnostic messages resolve through the same English/Bulgarian catalog and host translator. The paired fallback suites pass 19 cases each on JVM, JS browser, Wasm browser and iOS simulator, including live locale changes for Monaco and TemplateLayout and initial Bulgarian delivery for AG Grid. The [browser integration review](web-only-integration-review.md) records the DOM host, disposal and interaction proof needed before any JS-only adapter can claim one of these integrations. Native Compose equivalents can be declared by their own behavior without claiming compatibility with the named web library. Only English and Bulgarian fallback copy is shipped; other host locales use the documented fallback or a host translator.
