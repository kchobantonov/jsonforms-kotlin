# Renderer prevention paths (§15.8)

This records the constraints that the current Kotlin renderers prevent through interaction. It is an implementation inventory, not certification across targets. Schema validation still runs for imported data, unsupported keywords, hidden fields and edits made outside these controls. Explicit `restrict: false` allows the listed count, length or range violations to commit where the renderer supports that option; it does not disable validation or read-only rules.

| Renderer profile | Prevented interaction when restricted | Mutation-path check | Current evidence and limit |

| Ordinary array, expandable and table | Add above `maxItems`; delete below `minItems`. Move leaves the count unchanged. | Add button and click check count; the Add updater now rechecks the array snapshot and resulting `maxItems` count. Delete checks permission and array snapshot before updating. | Shared [Material table renderer](../material-renderers/src/commonMain/kotlin/com/chobantonov/jsonfroms/material/renderers/complex/MaterialArrayControlRenderer.kt) and [expandable layout renderer](../material-renderers/src/commonMain/kotlin/com/chobantonov/jsonfroms/material/renderers/layouts/MaterialArrayLayoutRenderer.kt); Cupertino delegates both with its dialog wrappers. Both preserve visible invalid imported values until Add repairs them. [Array action tests](../examples-compose/src/commonTest/kotlin/com/chobantonov/jsonfroms/examples/compose/ArrayActionPolicyUiTest.kt) and [count-boundary cases](../examples-compose/src/commonTest/kotlin/com/chobantonov/jsonfroms/examples/compose/ArrayCountRestrictionUiTest.kt) on JVM/iOS. |
| Tuple with editable tail | Tail Add above `maxItems`; trailing delete below `minItems`. | Free-entry chips | Token creation above `maxItems`; occurrence removal below `minItems`; duplicate insertion when `uniqueItems` is true. | Token and removal helpers check current array constraints. | Same two array-choice renderers and [chips UI cases](../examples-compose/src/commonTest/kotlin/com/chobantonov/jsonfroms/examples/compose/ChipsUiTest.kt); latest focused 14-case JVM suite passes. |
| Additional-properties editor | Add above `maxProperties` and delete below `minProperties`, counting declared and dynamic keys. Other editor paths and browser/Android interaction remain open. |
| Ordinary single-line/multiline text and Material anyOf text | New input beyond `maxLength`, counting Unicode code points; an already overlong value can be shortened. | Text change callback checks displayed-to-stored candidate before dispatch. | [Shared guard](../core/src/commonMain/kotlin/com/chobantonov/jsonfroms/core/util/RestrictedStringEdit.kt) and [mounted cases](../examples-compose/src/commonTest/kotlin/com/chobantonov/jsonfroms/examples/compose/StringRestrictionUiTest.kt). `pattern` is validation-only; it does not imply a mask. |
| Integer and number text | New inclusive or exclusive numeric-bound violations while allowing a move toward validity from invalid imported data. This is additional prevention beyond the §15.8 table; browser/Android interaction remains open. |
| Date, time and date-time | Picker selection and Apply outside supported inclusive/exclusive format bounds. | Picker confirmation rechecks the selection and current bound; complete typed/pasted range violations may commit with validation feedback. Partial input stays local. | Material/Cupertino temporal controls and [mounted bound cases](../examples-compose/src/commonTest/kotlin/com/chobantonov/jsonfroms/examples/compose/TemporalBoundsUiTest.kt). Unsupported comparators and external data remain validator concerns. |
| File control | Restricted file size and array `minItems`/`maxItems` on picker batches, removal and clear. | File selection and removal paths recheck count and known size, with pending read state. | [Extended file renderer](../extended-renderers/src/commonMain/kotlin/com/chobantonov/jsonfroms/extended/renderers/FileControlRenderer.kt); actual native picker interaction and browser/Android evidence remain open. |

The renderer source is the authority for the exact guard at a given interaction. This matrix marks gaps where the current tests do not prove keyboard delivery, a stale callback after a competing host update, native picker operation, or browser/device interaction. Read-only and enabled state are separate from `restrict`: renderer-owned data mutations must obey them even when prevention is disabled.
