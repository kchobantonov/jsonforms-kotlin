# Testing strategy and current harness

This project uses Kotlin `test` in common test source sets. The Android application and all shared UI are Compose. No dependency injection, mocking framework, Robolectric, screenshot baseline, or end-to-end test harness is configured. Tests can construct core state and renderer inputs directly; adding a DI framework is not needed for these tests.

## Focused tasks

| Change | First check |
| --- | --- |
| Schema, paths, store, validation | `:core:jvmTest` |
| Compose controller or dispatch | `:compose:jvmTest` |
| Extended renderer behavior | `:extended-renderers:jvmTest` |
| Fixture parsing and generated catalog | `:examples:jvmTest` |
| Demo wiring | `:examples-compose:jvmTest` and `:examples-compose:jvmJar` |

For focused `:examples-compose:jsBrowserTest` runs, pass `-Pjsonforms.skipWebcomponentResources=true`. The test harness does not load the separately built demo webcomponent, so this property leaves its production distribution out of `jsProcessResources`. Ordinary JS demo builds keep that resource dependency. A dry-run of `:examples-compose:jsProcessResources` confirms the webcomponent distribution is present by default and absent with the property. With limited disk space, compile `:examples-compose:compileTestDevelopmentExecutableKotlinJs` first, retain the synchronized test executable, remove only its generated incremental compiler cache, then run the browser task while excluding that compile and sync task. Do not count a successful bundle compile as a browser test result; inspect the browser XML for nonzero executed cases.

`extended-renderers/src/commonTest/.../TemplateSlotUiTest.kt` now uses the Compose Multiplatform `runComposeUiTest` harness and executes the imported Template/Slot fixture in both Material and Cupertino. The shared `ui-test` dependency is versioned with the Compose plugin. A JVM runner is configured. It verifies named overrides, fallback, nested composition, caller-data editing, missing and duplicate template diagnostics, recursive Template and Slot guards, and recovery after replacing a recursive template. `examples-compose/src/commonTest/.../AdditionalErrorsDemoUiTest.kt` also exercises the real demo in Material and Cupertino: two server errors, selective clearing by edit, clear action, and English/Bulgarian labels and messages. These JVM tests do not establish Android, iOS, JS, or Wasm UI parity.

`UnsupportedTemplateLayoutTest.kt` preserves the authored TemplateLayout payload and distinguishes unknown language, disabled script evaluation and unavailable engine. Four mounted JVM cases cover visible feedback and diagnostics in Material and Cupertino without dispatching template children outside their engine; the pure resolver case also runs on iOS simulator and Wasm browser. This is explicit unsupported behavior, not TemplateLayout engine conformance. `CodeProfileFallbackTest.kt` mounts the `options.format: "code"` notice in Material and Cupertino, edits an ordinary string through the native control, and confirms a converted JSON request does not mutate on mount. The registry selection case also passes on iOS simulator and Wasm browser. This fallback is not Monaco conformance.

`extended-renderers/src/commonTest/.../ImageViewUiTest.kt` mounts direct and scoped images in both renderer families, checks source and alt diagnostics with reference severity, translated accessible failure text, and exercises the imported presentation fixture's data and visibility changes. `ImageLoadingJvmTest.kt` verifies Coil decodes the fixture's SVG data URL and fetches the same SVG from a loopback HTTP server. The mounted tests also force an undecodable image, translate and retry its fallback, and recover with a valid URL without changing data. Non-JVM compilation is covered separately; browser and device loading remain unverified.

`SafeMarkdownTest.kt` checks the shared basic-profile AST renderer, including literal excluded constructs, styles, lists, soft and hard line breaks, policy-allowed custom links, refused targets, references, autolinks, and typography configuration precedence. `MarkupLabelUiTest.kt` mounts every Label section of the imported markup fixture in Material and Cupertino, checks link annotations and refusal diagnostics, switches English/Bulgarian translation, and verifies that unknown or disabled requests keep their original text. These are JVM semantics tests; browser link activation and device presentation remain open.

`LabelInterpolationTest.kt` exercises the strict portable expression subset, namespace gate, missing-data versus author errors (including out-of-range array indexes), literal braces, precedence and short-circuit operators, presence/membership, translation, locale-aware number/currency/percent/date/time/dateTime formatting, temporal validation, and Markdown substitution escaping. The earlier 18 methods executed and passed on JVM, JS browser, Wasm browser and the iOS simulator. A nineteenth case checks signed integer overflow and the exact minimum literal; a twentieth checks homogeneous numeric arithmetic, integer-only remainder and whole-valued double type retention. A twenty-first case checks cross-type numeric equality, exact ordering near the double precision boundary, list membership and nested JSON equality. A twenty-second checks Boolean ordering and mixed-type rejection. A twenty-third case covers ordinary single/double CEL strings, escape validation and quoted bracket keys. The full 23-case suite passes on JVM. All five new expression cases pass on iOS simulator and Wasm browser, and Android/JS compile; JS browser execution remains open. The shared locale test accepts the iOS formatter’s narrow no-break AM/PM space. `LabelInterpolationUiTest.kt` mounts all imported Label categories in both families, changes data, locale, host config/context and selected list item, and checks visible error diagnostics. It also tests live draft `item` values in table row, tuple and composite cell dialogs for both families, including Cancel isolation. `LocaleExpressionFormattingJvmTest.kt` sets a west-of-UTC viewer time zone and confirms calendar and clock values remain stable, an offset instant changes day and time, and an offset-free date-time retains its wall clock in each viewer zone, and daylight-saving overlaps choose the earlier instant while spring gaps normalize forward. Canonical CEL, remaining form-control integration and target interaction tests are open; mounted browser tests currently fail in the Skia test harness before rendering.

## Next harness work

1. Add semantic behavior tests for editing, owner error publication/disposal, focus, state restoration, and accessibility in both renderer families.
2. Enable Android device tests using the Android KMP plugin's device-test source set and the Android test runner. Use an emulator only for cases that need platform behavior.
3. Run shared Compose UI tests on iOS and Wasm where runners are available; document host prerequisites and failures. Check JS browser separately.
4. Add geometry and visual checks for narrow/wide, RTL, large font, Material/Cupertino, and light/dark demo states. Store reference screenshots only after behavior is stable.
5. Add a small end-to-end set for demo editing, settings persistence, and cross-platform navigation after the feature slices land.

Run full build and test suites at the baseline/final gates in `docs/extended-spec-plan.md`, or when an affected shared API creates broad integration risk. Fixture imports and compilation alone are not conformance evidence.

Compose testing setup follows the [current Kotlin Multiplatform UI testing guide](https://kotlinlang.org/docs/multiplatform/compose-test.html).
